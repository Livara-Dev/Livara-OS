# Your app icons

Open **Livara Settings → App icons**. Search by an app's name or desktop launcher ID, then click its pencil button to choose a local image. The undo button beside that app restores its original icon. **Only customized icons** finds your changes; **Include background launchers** also shows launchers normally hidden from the app grid. Refresh after installing an app. Large libraries load 75 rows at a time, with Show more for the rest.

This covers desktop launcher and dock icons for Livara apps, default GNOME/system apps, and other installed apps exposed through the desktop application catalog, including exported Snap and Flatpak launchers. It preserves desktop IDs, commands, arguments, localized app names, startup matching, D-Bus activation, actions and default-app associations. No sudo or system-package editing is needed. Each account has its own icon choices.

PNG, JPEG, WebP, SVG and ICO images are supported, along with the other installed GdkPixbuf formats. Compressed PNG entries in Windows ICO files are supported. Images are limited to 8 MiB, 8192 pixels on either axis and 16 megapixels; a square transparent image is usually the best choice. Livara keeps a static PNG up to 512 pixels across, retaining aspect ratio and transparency. You can move or delete your original image afterward. SVGs must be self-contained; inline PNG/JPEG/WebP artwork and internal references work, while external files, URL imports, scripts and embedded HTML are rejected.

Changes use a local override in `$XDG_DATA_HOME/applications/` (normally `~/.local/share/applications/`). Icon copies and private restoration records live in `$XDG_DATA_HOME/livara/app-icons/`. The actual installed launcher stays unchanged. Restore removes a Livara-created override, or restores the exact earlier user launcher if one existed before customization. Unrelated user overrides stay untouched. If an override is edited outside Livara afterward, the manager reports it and preserves those edits instead of overwriting them.

Icon paths change when the image changes, allowing the desktop to notice a new asset. Some running windows may need reopening, and some desktops need a new session to clear cached icons. A program's embedded branding, toolbars, website favicons, document-type icons and official Tor Browser's internal UI follow their own settings. Programs without a desktop launcher are outside this catalog. The ordinary image chooser does not launch applications.

A local desktop override can shadow upstream launcher changes until it is restored or customized again. Applying another icon to an originally system-provided launcher reads its latest installed desktop file. If an app is uninstalled, remove its remaining custom launcher with Restore before forgetting the override. These per-user files need persistent home storage to survive a live OS shutdown.

`tests/test_app_icons.py` checks launcher preservation, localized icons, Unicode IDs/search, Snap/Flatpak command fixtures, private backups, symlinks, rollback and restoration. `scripts/app-icons-smoke.py` optionally exercises the real GTK chooser, image decoders, Gio icon readback, filters, Restore and 800×600 layout in an isolated test profile. It needs the desktop launchers/wrappers installed or on PATH, plus the GUI test dependencies described in its header.
